# VPBuddy 行业模板模块产品需求

## 1. 文档信息

- 模块名称：行业模板
- 首期范围：网页生成模板
- 产品形态：Web 与桌面客户端共用同一套页面和接口
- 目标版本：待排期
- 需求状态：方案确认中

## 2. 背景与目标

VPBuddy 当前可以在会议过程中根据沟通内容生成 Demo，但用户仍需从空白状态描述页面需求。行业模板模块用于沉淀可复用的网页成果，让用户从已有行业场景快速进入会议协同。

首期目标：

1. 在 VPBuddy 全局导航中提供独立的“行业模板”入口。
2. 展示可搜索、筛选和预览的网页生成模板。
3. 用户点击“使用模板”后直接进入会议工作台，不增加中间配置步骤。
4. 所选模板在该会议中自动落为可查看、可下载、可继续迭代的 `Demo V1.0`。
5. 模板与应用结果均使用真实后端数据，不在正式环境展示 Mock 数据。

### 技术实现原则

本需求只定义产品行为和前端所需能力，不指定后端数据库、目录、任务框架或固定接口名称。后端应结合 VPBuddy 现有会议、交付物、Demo 版本、文件、鉴权和持久化框架确定最小改动方案。

行业模板不是一套新的会议系统。本次只新增模板入口，并在应用模板时为现有会议流程准备一个初始 `Demo V1.0`；进入会议后，其余功能和数据链路全部保持不变。

## 3. 核心定义

### 3.1 行业模板

行业模板是由 VPBuddy 平台维护的、可跨用户浏览的网页 Demo 母版，包含：

- 模板名称、行业、场景、适用角色和标签。
- 封面图与只读预览。
- 可运行的网页 Demo 文件包，包括 HTML、CSS、JavaScript 和必要的静态资源。
- 用于后续 AI 修改的模板上下文和生成约束。

### 3.2 应用模板

“应用模板”不是引用第三方网页，也不是仅在前端临时展示。应用成功后，后端应为当前用户创建一场会议，并将模板内容复制为该会议独立拥有的 Demo 初始版本。

模板母版后续更新，不得覆盖已经应用到会议中的 Demo。

### 3.3 Demo V1.0

- 模板应用后的初始成果固定标记为 `V1.0`。
- `V1.0` 必须可以直接预览、全屏展示和下载。
- 用户后续通过会议沟通或“发送给 VPBuddy”修改 Demo 时，沿用现有 Demo 版本机制生成新版本。
- 除 Demo 外，不自动生成需求文档、架构文档、任务拆解、API 设计和风险分析；这些材料仍由会议过程按现有逻辑生成。
- 录制、实时转写、会议记录、会议材料、VPBuddy 对话、AI 协同、其他交付物、下载和会议总结均沿用现有功能，不增加模板专用分支。

## 4. 用户入口与页面结构

### 4.1 导航入口

登录后左侧导航顺序调整为：

1. 工作台
2. 行业模板
3. 知识库

“行业模板”位于“知识库”正上方。现有隐藏的“设置”入口保持隐藏。

### 4.2 模板选择页

页面保持 VPBuddy 现有深蓝色桌面工作台视觉，不重新设计整体框架。

页面包含：

- 标题：行业模板。
- 模板数量：显示当前筛选条件下的真实结果数量。
- 搜索：支持按模板名称、行业、业务场景和标签检索。
- 行业筛选：首期建议包含全部、企业服务、电商零售、教育培训、内容营销、数据分析、文旅住宿。
- 排序：默认综合排序，后续可扩展最近更新和使用最多。
- 模板卡片：展示真实封面、模板名称、行业、场景摘要和推荐标记。
- 卡片操作：查看详情、使用模板。

页面状态：

- 加载中：使用固定尺寸骨架屏，避免布局跳动。
- 空结果：显示“没有匹配的行业模板”，保留搜索和筛选条件。
- 加载失败：显示错误原因与“重新加载”操作，不回退到 Mock 数据。

### 4.3 模板详情

点击“查看详情”后，在当前页面打开详情弹窗或侧边详情层，包含：

- 模板完整名称与封面。
- 所属行业、业务场景、适用角色和标签。
- 页面模块说明。
- 可交互或只读的网页预览。
- 主操作“使用模板”。

关闭详情后保留原搜索、筛选和滚动位置。

## 5. 核心用户流程

### 5.1 正常流程

1. 用户登录 VPBuddy。
2. 点击左侧“行业模板”。
3. 浏览、搜索或筛选模板。
4. 点击模板卡片中的“使用模板”。
5. 按钮立即进入“正在应用”状态并禁止重复点击。
6. 前端调用后端提供的模板应用能力。
7. 系统按现有会议规则创建一场属于当前用户的新会议。
8. 系统按现有交付物与版本规则将模板保存为该会议的 `Demo V1.0`。
9. 后端返回前端进入会议并定位该 Demo 所需的信息。
10. 前端直接进入该会议工作台，并默认打开“交付物”页签中的 Demo。
11. Demo 在预览区域加载完成后可直接操作。

### 5.2 新会议默认规则

- 会议名称默认使用模板名称，例如“电商经营数据看板”。
- 用户可沿用现有会议标题双击重命名能力修改名称。
- 新会议不自动开始录音，录制按钮保持“开始录制”。
- 新会议的会议记录、会议材料和 VPBuddy 对话记录均为空。
- 会议列表中的状态以后端会议状态为准，不由前端伪造“进行中”。

### 5.3 失败流程

- 创建会议失败：停留在模板页，恢复按钮并显示明确错误。
- Demo 初始化失败：后端不得返回应用成功，也不能留下用户可见的错误完成状态。
- 页面跳转后 Demo 加载失败：保留会议和 Demo 元数据，提供重新加载，不生成占位 Demo。
- 网络超时：允许用户重试；重复点击或请求重试不得产生重复会议或重复 Demo。

## 6. 模板首期内容范围

首期只迁移案例库中“产物为网页/网站”的模板，建议优先覆盖：

- 科技公司动态官网。
- 电商经营数据看板。
- 企业碳管理仪表盘。
- 花店品牌官网。
- 招生宣传网页。
- 临海民宿产品页。
- 教学网站。
- 达人矩阵管理看板。
- 外卖商品页面。
- 活动策划测算网页。

迁移原则：

- 迁移模板结构、行业元数据和可复用生成约束。
- 模板文件和图片资源存入 VPBuddy 自有存储，不依赖第三方页面在线可用性。
- 不使用第三方网页 iframe 作为正式 Demo。
- 上线前确认模板内容和素材具备可使用、可迁移的授权。

## 7. 前端所需数据语义

后端内部数据模型由后端团队结合现有框架决定。前端只要求能够获得以下信息：

### 7.1 模板目录信息

- 稳定的模板标识。
- 模板名称、行业、场景、摘要和标签。
- 封面或预览资源。
- 推荐状态、可用状态、总数和分页信息。
- 支持搜索、行业筛选和排序所需的数据。

### 7.2 模板应用结果

- 应用是否成功以及可判断的失败信息。
- 前端进入目标会议所需的会议信息。
- 前端定位初始 Demo 和版本所需的信息。
- 初始 Demo 已持久化、可预览且可下载的状态。

## 8. 后端能力需求

所有能力沿用现有登录凭证和用户权限体系。具体采用扩展现有接口还是新增接口，由后端结合 VPBuddy 当前技术框架决定，并在实现后提供最终接口文档。

### 8.1 模板列表

支持获取真实模板目录，以及关键词搜索、行业筛选、排序和分页。

### 8.2 模板详情与预览

支持读取模板完整说明和有效预览。优先复用现有文件读取、Demo 预览与静态资源能力，不向前端暴露密钥、服务器路径或内部系统提示词。

### 8.3 应用模板

提供一个前端可以明确调用的业务能力，使系统按现有规则创建会议，并将模板保存为普通 Demo 的初始 `V1.0`。应用成功后返回前端进入会议和选中 Demo 所需的信息。

后端可以选择：

- 在现有创建会议流程中增加可选模板参数；或
- 提供一个复用现有会议和 Demo 服务的组合能力；或
- 采用更符合当前代码结构的等价方案。

产品只要求最终结果一致，不限制具体实现。

### 8.4 一致性与现有能力复用

- 成功时，会议和初始 Demo 均已持久化并可读取。
- 失败时，不返回已完成，也不留下用户可见的错误空 Demo。
- 重复点击、超时重试或网络重连不产生重复会议和重复 Demo。
- 初始 Demo 继续使用现有预览、全屏、下载、版本迭代和会议总结能力。

## 9. 前端状态与行为

- 模板列表、详情和应用结果全部以后端返回为准。
- 搜索和筛选条件在模板页内保留，离开页面后可在本次会话中恢复。
- “使用模板”发起请求后显示进度状态，禁止二次提交。
- 应用成功后将返回的 `meeting_id` 设置为当前会议，再加载会议详情和 Demo 版本。
- 默认切换到会议工作台的“交付物”页签并选中 Demo。
- Demo 加载期间使用局部 loading，不允许整页空白闪烁。
- 前端不得把模板写入个人知识库或会议材料列表。
- 前端不得用本地 Mock Demo 替代接口失败结果。

## 10. 权限与数据边界

- 模板母版：平台级数据，登录用户只读。
- 模板应用记录：归属于当前用户。
- 应用后会议与 Demo：归属于当前用户，沿用现有会议权限。
- 个人知识库：不包含模板母版和模板 Demo。
- 会议材料：不包含模板母版；只有用户后续主动上传到该会议的文件。
- 模板应用不向第三方网站发送用户会议内容。

## 11. 非功能要求

- 首屏列表在正常网络下应尽快展示骨架并逐步加载真实内容。
- 模板卡片固定尺寸，图片加载不得造成页面跳动。
- 支持 Web 和 Electron 客户端常见桌面分辨率及系统缩放比例。
- 所有文本不得溢出；长模板名最多两行，完整名称通过详情查看。
- 模板封面采用懒加载，失败时显示统一的 VPBuddy 模板占位图。
- 接口失败、模板应用和页面跳转写入客户端 Log，但不得记录令牌、密码或敏感提示词。

## 12. 验收标准

1. 左侧导航出现“行业模板”，顺序位于“工作台”和“知识库”之间。
2. 点击入口进入独立模板页，原工作台和知识库功能不受影响。
3. 页面模板数量、卡片、搜索结果和筛选结果均来自后端。
4. 搜索、行业筛选、排序、查看详情和关闭详情均可正常操作。
5. 点击“使用模板”后按钮立即显示处理中，重复点击不会创建多份数据。
6. 应用成功后直接进入新会议工作台，不出现二次配置页面。
7. 新会议名称默认为模板名称，且可通过现有能力修改并保存后端。
8. 会议不会自动录制，录制状态和计时均保持初始值。
9. 交付物默认选中 Demo，版本显示为 `V1.0`。
10. Demo 可正常预览、全屏和下载，刷新页面或重新登录后仍可读取。
11. 模板不会出现在个人知识库或会议材料列表中。
12. 应用失败时不展示假成功、不加载 Mock Demo，并可重试。
13. Web 与桌面客户端页面无文字重叠、元素溢出或异常缩放。

## 13. 后续迭代

首期完成后可继续增加：

- 模板收藏与最近使用。
- 企业私有模板。
- 模板后台发布、下架和排序管理。
- 应用前填写品牌、颜色、企业名称等变量。
- 基于当前会议已有内容推荐模板。
- 将已完成的优秀 Demo 保存为个人或企业模板。
